# GitHub Repository Explorer

Учебный **React Web + TypeScript + Vite**: все три обязательных этапа и Bonus с собственным hook. [Условие](docs/ASSIGNMENT.md) · [Полный разбор всех файлов](docs/MANUAL.md).

Маршрут: **подготовить Mac → клонировать → Step 1 → Step 2 → Step 3 → Bonus → тесты и сборка → объяснить решение**.

## 1. Подготовить Mac

Нужны **Git**, **Node.js 24** и входящий в Node.js **npm**. Это обычный сайт React + TypeScript: Expo, Xcode Simulator, Android Studio, Java и MySQL для него не нужны.

Откройте Terminal и проверьте:

```bash
git --version
node --version
npm --version
```

Если Git не найден или macOS предлагает установить инструменты разработчика, установите **Command Line Tools**:

```bash
xcode-select --install
```

Дождитесь окончания системной установки, откройте новое окно Terminal и повторите `git --version`. Полный Xcode для этого сайта не требуется. [Инструкция Apple](https://developer.apple.com/documentation/xcode/installing-the-command-line-tools/).

Если Node.js отсутствует или установлена другая ветка, установите **Node.js 24 LTS** через официальный macOS Installer на [nodejs.org](https://nodejs.org/en/download). После установки перезапустите Terminal. Если у вас уже есть nvm, вместо установщика достаточно:

```bash
nvm install 24
nvm use 24
```

Не устанавливайте npm отдельно и не выполняйте `sudo npm install` в проекте.

## 2. Склонировать репозиторий

Следующие команды создают отдельную папку внутри `~/Projects`:

```bash
mkdir -p "$HOME/Projects"
cd "$HOME/Projects"
git clone https://github.com/MaximillianVoss/github-repository-explorer.git
cd github-repository-explorer
npm ci
```

Если папка с таким именем уже существует, не удаляйте её: перейдите в имеющийся клон или выберите другое имя, например `git clone https://github.com/MaximillianVoss/github-repository-explorer.git github-repository-explorer-copy`. В этом случае следующая команда — `cd github-repository-explorer-copy`.

`npm ci` берёт точные версии из приложенного `package-lock.json`. Команда переустанавливает только зависимости в `node_modules`, не удаляет исходники. Все следующие команды выполняются из папки с `package.json`, не из родительского каталога.

Запланирован переход репозитория в private **26 сентября 2026 года в 12:00 по московскому времени (Europe/Moscow)**. Успейте склонировать до этого момента. Локальная копия продолжит работать после перехода; для нового клонирования и `git pull` затем потребуется приглашение владельца и авторизация. Сам этот README не меняет видимость репозитория.

## 3. Проверить все версии

```bash
npm test
npm run build
npm run build:stages
```

`build` собирает финальную Bonus-версию, `build:stages` — отдельные Step 1, 2 и 3. Каждая версия хранит свою сборку `dist`.

## 4. Запустить нужный этап

Все команды ниже выполняются **из корня клона**. Не переходите в `stages/step1` перед запуском.

| Версия | Команда | Что изучаем |
| --- | --- | --- |
| Step 1 | `npm run dev:step1` | Начальная загрузка репозиториев по слову react. |
| Step 2 | `npm run dev:step2` | Пользователь вводит слово; запрос только по Search / Enter, не через effect. |
| Step 3 | `npm run dev:step3` | Фильтр уже загруженного списка без новых API-запросов. |
| Bonus | `npm run dev` | Та же функциональность через собственный `useRepositories` hook. |

Для начала выполните:

```bash
npm run dev:step1
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173), либо фактический адрес Vite из терминала. Для следующего этапа нажмите **Control + C**, затем запустите его команду из таблицы. Остановка не удаляет папку или исходники. Этапы не копируют и не перезаписывают файлы друг друга.

Если порт занят, явно выберите свободный, например:

```bash
npm run dev:step2 -- --port 5178 --strictPort --open
```

Откройте [http://127.0.0.1:5178](http://127.0.0.1:5178). Если он занят, замените 5178 на 5179. Для Bonus аналогично: `npm run dev -- --port 5178 --strictPort --open`. Не останавливайте чужое приложение ради освобождения порта.

## 5. Просмотреть готовую сборку

После `npm run build`:

```bash
npm run preview -- --port 4173 --strictPort --open
```

Bonus откроется на [http://127.0.0.1:4173](http://127.0.0.1:4173). Для сборки Step 1 после `npm run build:stages`:

```bash
npm run preview -- stages/step1 --port 4174 --strictPort --open
```

Step 1 откроется на [http://127.0.0.1:4174](http://127.0.0.1:4174). Для Step 2/3 замените имя каталога. Это локальный просмотр, а не хостинг в интернете.

## 6. Что важно объяснить

- Step 1 использует `useEffect` для запроса при открытии.
- Step 2/3/Bonus вызывают запрос из `handleSearch` при отправке формы; ввод букв сам по себе не обращается к API.
- `searchRepositories` проверяет вход и ответ HTTP, берёт список из `items`.
- `filterRepositories` использует `Array.filter` по `full_name`, без сети.
- `RepositoryTable` получает данные через props.
- Bonus `useRepositories` объединяет состояние и загрузку, но не запускает поиск автоматически.
- Bonus предлагает альтернативы: здесь выбран **свой hook**, TanStack Query не требуется.
- Токен GitHub не нужен для учебного публичного поиска. Не вставляйте токены в браузерный код или `VITE_...`.
- Три этапа лежат в `stages`; требование создавать Git-ветки в этом условии отсутствует.

## Если что-то не запускается

| Сообщение / ситуация | Что сделать |
| --- | --- |
| `npm: command not found` | Установить Node.js 24, перезапустить Terminal. |
| `ENOENT package.json` | Перейти в папку клона, где лежит `package.json`. |
| `npm ci` требует lock-файл | Убедиться, что клонирован весь репозиторий: файл `package-lock.json` входит в него. |
| Git пишет `Repository not found` | Проверить адрес; после перехода в private запросить доступ у владельца. |
| `react/jsx-runtime` не найден | Запустить `npm ci` в корне и перезапустить редактор. |
| API недоступен | Проверить интернет; сообщение об ошибке не означает, что сайт не запустился. |
| В preview старый результат | После изменения исходников снова выполнить `npm run build`. |

После успешного клонирования интернет всё ещё нужен для установки зависимостей и реальных API-запросов. Тесты подменяют ответы API и не расходуют внешний лимит.

Клон этого репозитория — учебная основа, а не автоматическая сдача в Classroom. Для сдачи в репозиторий преподавателя переносите нужные файлы осознанно, сохраняйте его `.github` и правила проверок. Не отправляйте `node_modules`, токены, пароли или личные файлы.

Здесь не заявляется проверка на конкретном Mac или отправка работы преподавателю. Поле `"private": true` в `package.json` запрещает случайную публикацию npm-пакета и не определяет видимость репозитория GitHub.
