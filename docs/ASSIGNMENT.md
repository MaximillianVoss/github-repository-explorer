# GitHub Repository Explorer — условие

Краткий русский пересказ задания курса; оригинальные скриншоты и переписка не публикуются. **5 баллов** за три обязательных этапа; Bonus — дополнительная часть.

## Step 1 — список репозиториев, 1 балл

При открытии компонента загрузить репозитории с фиксированным словом `react`:

```text
https://api.github.com/search/repositories?q=react
```

Показать полное название каждого репозитория (`full_name`) и кликабельную ссылку (`html_url`). Массив находится в `items` ответа.

## Step 2 — пользовательский поиск, 2 балла

Добавить поле ключевого слова и кнопку поиска. Новый запрос отправляется из обработчика действия пользователя, не через `useEffect`. Список обновляется по результату. Пустое значение и строка из пробелов должны приводить к сообщению, а не запросу.

## Step 3 — локальная фильтрация, 2 балла

Добавить отдельное подписанное поле фильтрации по имени репозитория (`full_name`). Фильтровать только уже загруженный массив. Набор текста в фильтре не должен повторно запрашивать GitHub API.

## Bonus

Вынести логику загрузки в собственный React hook **или** использовать библиотеку вроде TanStack Query. В данном репозитории выбран собственный hook.

## Самостоятельная проверка без подсказки решения

- Чем отличается момент загрузки в Step 1 и Step 2?
- Как убедиться, что локальная фильтрация не делает HTTP-запрос?
- Как отличаются пустой результат поиска, пустой результат фильтра и сетевая ошибка?
- Какой код можно переиспользовать между компонентами?

Git-ветки условием не предписаны. Все этапы предоставлены отдельными папками для сравнения; запуск и сдача — отдельные действия.
